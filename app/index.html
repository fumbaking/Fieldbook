Access requests

Anyone who opened the link and gave a name. Approve them here; once approved they move into User logs above.

Active sessions

Standing access lasts until you deactivate it. A timed session counts down from the moment you approved it.

Admin code

Set your own code here. It is never written into this page — only a hash of it is stored, and the database lets no one but you read that hash.

Guest code

The code you hand to visitors. They still give their name, and you can deactivate any of them from Active sessions.

What's in the database

Live counts straight from the store, so you can always see what is really saved.

Decision history

Every approval, denial and code change you have made, newest first.

What this does and doesn't do. Approvals, deactivations and this history are stored with owner-only write permission, so a guest cannot approve themselves — the database refuses the write. But the page's text is still delivered to every browser that opens the link, so someone technical who is denied can read the source. Treat this as session control and an audit trail, not as a seal on the content. A guest is identified by the name they typed and by their browser, so the same person on a new device makes a new request, and a name is only as truthful as the person typing it.
